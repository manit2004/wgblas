    Module devdocs/shaders

    Structure

    shaders/*.wgsl — one WGSL compute shader per BLAS routine (sscal, saxpy, sdot, …).

    routineShaders below is the single source of truth: routine name → the WGSL source(s) its getPipeline() calls actually reference, verified against every src/<routine>/<routine>.mjs rather than inferred from naming convention (see its doc comment for the exceptions). Each shader is imported right above the line that adds it — the import is the mapping entry, no separate block to cross-reference. shaderSources, the flat name → source registry the browser bundle's runtime lookup needs, is derived from routineShaders rather than hand-duplicated, so the two can never drift apart. In Node.js neither is read — shaders are readFileSync from disk directly; scripts/build-browser.mjs inlines this module into the browser's IIFE bundle via esbuild instead.

    Cross-shader patterns

    Workgroup size: 64 by default, tuned upward for tiled matmul. Every 1D shader (all of Level 1, the row-per-workgroup Level 2 kernels, the reduction/f64 families, strsv's three stages) declares const WGS: u32 = 64 and @workgroup_size(64) — 64 is the minimum maxComputeInvocationsPerWorkgroup guaranteed across all WebGPU devices, so it works everywhere without querying device limits. The one-thread-per-matrix-element 2D shaders (symmetrize, triangularize, block_transfer) use @workgroup_size(8, 8) — still 64 threads total, just addressed as (row, col) via global_invocation_id.yx instead of a flat index. sgemm/sgemmtr's tiled kernels break the pattern deliberately: 256 threads (sgemm_small, BM=BN=32) or 128 (sgemm_large, BM=BN=64) — sizes an autotuning sweep (see sgemm_large.wgsl's header) found faster than 64 for register-blocked matmul, which needs enough threads per workgroup to hide shared-memory tile loads.

    Single bind group. All bindings use @group(0). This means the JS side always calls pipeline.getBindGroupLayout(0) — no secondary groups to track. Binding order is consistent everywhere too: read-only inputs first, then in-place/output read_write buffers, with the uniform Params struct always last.

    The @binding indices must match the position of each resource in the array passed to createBindGroup — it assigns binding: 0, 1, 2 … sequentially, with resultBuffer appended last.

    All counts and strides are u32. n, x_inc, y_inc, and any other index fields in the Params uniform struct are unsigned. This avoids implicit sign-extension when they appear in index expressions like id * params.x_inc.

    Grid-stride loops, not one-thread-per-element. Elementwise and row-per-workgroup kernels loop for (var id = gid.x; id < params.n; id += num_wg.x * WGS) (or the wgid/nwg row equivalent) rather than dispatching exactly n threads — so JS can dispatch a workgroup count decoupled from problem size, staying under maxComputeWorkgroupsPerDimension regardless of how large n/m gets (see sgemv_n.wgsl's header for this in the row-per-workgroup case).

    4-way ILP unrolling with a scalar tail. Every reduction, sgemv/sger/ssyr/ssyr2, and their f64 counterparts split their range into n4_floor = (n / (4*stride)) * (4*stride), processed 4 elements per iteration through four independent accumulators (acc0..acc3, naming consistent across files) so the GPU can pipeline memory requests instead of serializing them behind one dependency chain, then fall back to a plain scalar loop for the remainder.

    One parallel tree reduction shape, reused everywhere. Any kernel that turns per-thread partial results into one per-workgroup value — every Level 1 reduction, the row-per-workgroup Level 2 kernels, strsv_update, and the standalone reduction/*.wgsl second-pass shaders — writes into a var<workgroup> scratch/tile: array<f32, 64>, then runs the identical for (var s = WGS/2; s > 0; s >>= 1) { if (lid.x < s) { … } ; workgroupBarrier(); } halving loop. isamax/idamax and the two argmax reduction shaders carry a parallel tile_idx array through the same shape, breaking ties toward the lower index.

    Two-pass reduction dispatch. sdot/sasum/snrm2/isamax and their f64 counterparts dasum/idamax are always pass 1: dispatched as exactly 2 * WGS workgroups, each writing one partial. reduction/sum.wgsl/argmax.wgsl (and their *F64 twins) are always pass 2: one workgroup, reducing those 2 * WGS partials to the final scalar — documented explicitly in each pass-1 shader's header.

    Shared numeric conventions for flag fields. uplo is always 0 = lower, 1 = upper; trans is always 0 = no-transpose, 1 = transpose; diag is always 0 = non-unit, 1 = unit (substitute 1.0 for the diagonal without reading it). Identical meaning in every shader that has the field — ssymv, strmv, ssyr/ssyr2, sgemm/sgemmtr (as transA/transB), symmetrize, triangularize, and the whole strsv_* family.

    select() over branching for uniform control flow. The tiled/2D kernels (sgemm/sgemmtr/symmetrize/triangularize/block_transfer) and dasum's tail lean on select(falseVal, trueVal, cond) rather than if, particularly right before a workgroupBarrier() — WGSL requires uniform control flow across a barrier, so a value needed conditionally is computed unconditionally via select() and only the write is guarded.

    f64 shaders mirror their f32 twin, arithmetic swapped for double-double safety. dasum/idamax/reduction/sumF64/reduction/argmaxF64 are structurally identical to sasum/isamax/reduction/sum/reduction/argmax — same loop shape, same tree reduction — with plain +/>/== replaced by ddAddProtected/ddGreater/ddEqual on DD (hi, lo) pairs (Dekker's algorithm, f64/dekker.wgsl). Those f64 helper files have no bindings or entry point of their own — pure function libraries concatenated into a consumer's module by getPipeline's array-of-names form (WGSL has no #include), with f64/dekker.wgsl always concatenated first since it defines the DD struct the others use but don't redefine (WGSL errors on a duplicate struct once concatenated).

    Entry points don't need to be named main. loadShader (see util/pipeline.mjs) omits an explicit entryPoint whenever it's the default "main", letting WebGPU auto-detect the single @compute function in the (possibly multi-file-concatenated) module regardless of its real name — so dasum_main, strsv_invert_block_main, etc. work without every shader having to literally be called main; names beyond that are for readability in devtools/profiler output, not a functional requirement.
